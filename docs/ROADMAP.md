# 로드맵 — 모바일 우선

작성: 2026-10-08 · 기준: Claude Code 2.1.293 mod API 타입, `9ed586f`

## 범위부터

모바일에서 claude-hangul이 실시간으로 조합할 수 있는 경로는 하나다.
**태블릿·폰 + 외장 키보드 → 터미널 앱(SSH/mosh) → 호스트의 Claude Code TUI.**

| 경로 | 동작 | 근거 |
|---|---|---|
| 터미널 앱으로 SSH/mosh 접속 | 된다. 키가 ASCII로 와서 `prompt.edit` 로 조합 | `PromptEditInput` origin 은 `composer` 뿐 |
| Claude 앱 · Remote Control | 실시간 조합 안 됨. 글은 `prompt.submit` 에 통째로 도착 | 타입의 `bridge` origin, [Remote Control 문서](https://code.claude.com/docs/en/remote-control) |
| claude.ai/code 클라우드 세션 | 플러그인이 로드되지 않음 | [settings in cloud sessions](https://code.claude.com/docs/en/settings#settings-in-cloud-sessions) |
| 화면(소프트) 키보드 | 대상 아님. 자동완성이 단어 단위로 보내 키 묶음처럼 보인다 | Blink·Prompt 키보드 문서 |

세벌식이 모바일에서 막힌 상황은 사실이다. iPadOS·iOS는 외장 키보드용 세벌식 입력 소스가 없고, 서드파티 키보드 확장은 하드웨어 키를 받지 못한다.
Android는 기본 키보드(삼성·Gboard)에 없지만 별도 입력기를 깔면 된다. 그래서 Android에서 내세울 점은 "입력기 설치 없이, 한/영 키 없이, 어느 터미널 앱에서나 같게"다.
iOS SSH 앱에서는 OS 한글 IME로 Claude Code에 한글을 치면 자모가 깨진다. 업스트림 이슈 [#15705](https://github.com/anthropics/claude-code/issues/15705)와 [#23226](https://github.com/anthropics/claude-code/issues/23226)은 둘 다 NOT_PLANNED로 닫혔다. claude-hangul은 ASCII만 받기 때문에 이 문제를 피한다. 두벌식 사용자에게도 해당한다.

## P0 — 0.1.2 모바일 안정화

모두 작은 작업이다. 3·4·5는 코드 탐침으로 버그를 재현했다.

### 1. README 범위·과장 문구 정리 (문서) — 완료
- 위 범위 표를 README에 넣는다. 외장 키보드 전용이라고 적는다.
- "칠 방법이 없었다"를 "iPhone·iPad는 외장 키보드로 세벌식을 칠 방법이 없고, Android는 별도 입력기가 필요하다"로 고친다.
- "키가 몇 개씩 묶여 와도 한 글자씩"은 실제 조건(줄바꿈 없는 ASCII 8글자 이하)에 맞춘다. 원격 실측이 아직 없다고 밝힌다.
- iPad 설정을 구체적으로 적는다. 설정 > 일반 > 키보드 > 하드웨어 키보드 > Caps Lock으로 언어 전환 끄기(버전마다 이름이 다를 수 있음), Globe·⌃Space 전환도 끈다. 실제 Caps Lock이 켜지면 390·최종에서 숫자·기호가 나온다고 경고한다.
- 매번 `/hangul 390` 을 칠 필요 없이 호스트 셸 프로필에 `HANGUL_LAYOUT=390` 을 두면 된다고 안내한다.
- README와 SPEC의 테스트 개수(141/135/111/123)가 서로 다르다. 숫자를 빼거나 어느 러너 기준인지 적는다.
- **확인:** 문서 리뷰.

### 2. 실기 추적 세션 + 버스트 게이트 보강 — 코드 완료, 실기 세션 남음
- `editor.ts:104` 의 `e.key === undefined` 를 `e.key == null` 로 바꾼다. 엔진이 `key` 를 빼고 보내는지 `null` 로 보내는지 아직 모른다. `null` 로 오면 지금 버스트 처리 전체가 동작하지 않는다(탐침: 390 `mfs` + `{key:null,"kgw"}` → `한kgw`).
- `HANGUL_TRACE` 에 `'key' in e`, `typeof e.key`, `origin`, inputText 길이, shift 여부를 추가로 남긴다.
- iPad(Blink)와 Android(Termux)에서 ssh, mosh, mosh+tmux 세 경로를 돌려서 다음을 기록한다.
  - 실제 묶음 크기, DEL·BS가 묶음 안에 섞이는지
  - 화살표나 터치로 커서를 옮길 때 `prompt.edit` 가 오는지
  - Caps Lock 키가 어떤 모양으로 오는지
  - 밑줄 표시와 상태줄이 화면에 어떻게 보이는지
- **확인:** key:null 버스트 단위 테스트. 추적 로그를 `docs/SPEC.md` 에 첨부.

### 3. 조합 중인 영어 단어 앞쪽을 편집할 때 위치가 어긋나는 버그 — 완료
- 열린 영어 단어(`hel` 이 화면에 `녀l` 로 보이는 상태)를 키 그대로 되돌리면 길이가 바뀐다. 이때 `commitAndPass` 가 그 앞쪽 위치까지 무조건 밀어서 엉뚱한 곳이 편집된다(`editor.ts:185-192`).
- 탐침(390 `ab 녀l`): ctrl+u → `a` 가 남음, 0..1 백스페이스 → `a hel`, Home → 커서 1.
- 화살표·Home 이동도 같은 경로를 타서 영향이 크다.
- 고치는 법: 앵커 이후 위치만 민다. 조합 구간 밖에서 키를 칠 때도 열린 단어를 친 키로 되돌린다.
- `/hangul off`·레이아웃 전환 때 남는 경우는 뺐다. 명령은 입력 맨 앞에서만 인식되어 열린 단어와 함께 보낼 일이 없다.
- **확인:** ctrl+u·백스페이스·Home·단어 밖 입력·`/`·←·마지막 글자 치환 테스트.

### 4. 보내기(commitForSubmit) 방어 — 완료
- `prompt.submit` 이 Remote Control(`bridge`)이나 SDK에서 온 글에도 조합 확정을 돌린다(`register.tsx:75-80`). `origin.kind === 'composer'` 일 때만 돌린다.
- 확정할 때 앵커 위치의 글이 화면 글과 같은지 확인하지 않는다. 탐침: 앞에 한 글자가 끼면 ` hel` → `hell` 로 잘못 보내진다. 다르면 손대지 않는다.
- **확인:** 정상 확정, 어긋난 텍스트, bridge origin 세 경우를 테스트.

### 5. docs/mobile.md 짧은 가이드 — 초안 완료, 확인한 앱 표는 실기 후
- 직접 써 본 클라이언트만 적는다. 표에 '미검증'만 늘어놓지 않는다.
- 공통 체크리스트: OS 입력 언어 영어, 언어 전환 단축키 끄기, 자동완성 끄기, `mosh --predict=never`(`-n`), UTF-8, tmux.
- 증상 → 원인 표: 자모가 깨짐 → OS가 한글 IME 상태 / 숫자가 나옴 → Caps Lock / 영어가 잠깐 보였다 바뀜 → mosh 예측 에코.

## 0.2.0 — 단어 판정 (완료)

작성자 대화 기록을 시간순으로 나눠 앞 70%는 learn 흉내, 뒤 30%는 시험으로 썼다. 기록에서 나온 단어는 저장소 데이터에 넣지 않았다.
남은 한계: 흔한 한 음절 한글과 겹치는 영어(`rm`→`해`, `kr`→`개`)는 learn 없이 못 가른다. 390 `UI`→`78` 처럼 시프트 숫자와 겹치는 대문자 약어도 남았다.

## P1 — 실측 데이터 보고 결정

### 6. 버스트 규칙을 데이터로
고정 8글자 기준은 양쪽으로 틀린다.
- mosh는 250ms 단위로 몰아 보낸다. 끊겼다 이어지면 9글자 이상이 한 번에 와서 원문으로 들어간다(탐침 `한글mfskgwmfs`).
- 짧은 붙여넣기 `git` 은 조합돼서 두벌식에서 `햣` 이 된다.

후보 규칙: "조합 중이고 이어 붙는 위치면 길이와 상관없이 친 키로 본다. 아니면 N글자 이하만 친 키로 본다." N은 2번 데이터로 정한다.
API에는 붙여넣기 표시가 없어서 이걸로 구분할 수는 없다.
- **확인:** `한글한글한`, `git`, DEL 섞인 묶음 테스트.

### 7. 응답 대기 중 엔진이 그대로 넣은 키 복구
비동기 훅이 끝나기 전에 친 키를 엔진이 원문으로 넣는 경우다. claude-vime에서 보고됐고, 탐침 결과는 `하s글` 이다.
2번 추적에서 실제로 일어날 때만 처리한다. 원래 Android 원격 보고의 원인일 수 있다.

### 8. OS 한글 IME가 섞였을 때 한 번만 경고
키가 있는 한 글자 입력이 호환 자모이거나 "자모 → BS → 음절" 패턴일 때만 토스트를 한 번 띄운다. 붙여넣은 한글에는 반응하지 않는다.
Caps Lock 경고는 2번에서 실제 모양을 본 뒤 정한다.

### 9. 문장 중간에서 잠깐 영어로 빠지는 방법
지금은 줄 맨 앞의 `/hangul` 로만 끄고 켤 수 있다. 모바일 외장 키보드에는 한/영 키도 없다.
두벌식 `git` → `햣` 처럼 영어가 우연히 음절이 되는 경우를 위해, `prompt.edit` 까지 오는 ctrl 조합(예: ctrl+u는 오는 것이 확인됨) 하나를 토글로 쓴다. 어떤 조합이 오는지는 2번에서 확인한다.
